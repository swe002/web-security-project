SQL Injection (SQLi)

Query a mock database with unescaped input. Extract passwords and hidden schemas using boolean, error, or union-based payloads.

Cross-Site Scripting (XSS)

Test both Reflected and Stored XSS fields. Craft payloads to steal session cookies, hijack requests, or modify site styling.

Broken Authentication

Exploit user enumeration error messages, perform a credential dictionary attack, and bypass admin checks via cookie tampering.

Command Injection

Execute shell command chains directly inside the Linux container file system. Read configuration files and scan the system.

Insecure Direct Object References

Bypass authorization filters by iterating invoice numeric indices and exposing critical administrative financial files.

Vulnerability Verification & Tools Setup Guide

Learn how to configure your security software suite to inspect, identify, and audit these vulnerabilities.

1. Docker Setup

Deploy the application locally in an isolated networking environment:

# Build and run the container
docker compose up --build

# Verify container is running
docker ps

Once up, the lab is reachable at http://localhost:3000.

2. Reconnaissance with nmap

Verify active ports, OS classification, and services running inside the container:

# Scan local port 3000 to identify service and version details
nmap -A -p 3000 localhost

# Scan for common HTTP vulnerabilities on port 3000
nmap --script http-enum,http-title -p 3000 localhost

3. Intercepting Requests with Burp Suite / OWASP ZAP

To inspect and edit parameters, cookies, and payloads before they reach Node.js:

  1. Launch Burp Suite or OWASP ZAP on your host/Kali Linux VM.
  2. Configure your web browser to proxy traffic through the local proxy listener (defaults: 127.0.0.1:8080 for Burp, 127.0.0.1:8090 for ZAP). Or use Burp's built-in Chromium browser (easiest: no proxy setup required).
  3. Turn Intercept ON in Burp (Proxy -> Intercept).
  4. Trigger any action in this lab. Edit the parameters in transit (e.g. changing SQL inputs or cookies) and click Forward.

4. Packet Captures with Wireshark

Wireshark captures unencrypted HTTP traffic sent over the virtual docker bridge:

  1. Identify your Docker bridge interface (usually docker0 on Linux, or inspect loopback lo / localhost interface).
  2. Launch Wireshark (run as administrator/root) and double click the target network interface.
  3. Set a filter to isolate only port 3000: tcp.port == 3000.
  4. Perform actions in the Broken Authentication lab. Right click any captured TCP payload, and select Follow -> TCP Stream. Observe plaintext credentials and cookie variables traveling across the network!
